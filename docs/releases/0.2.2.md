# JV Desktop 0.2.2

- Validated public JV support codes are now visible and selectable for copying in Desktop. Terminal remote failures can show codes such as `JV-SVC-002` and `JV-TIMEOUT-001` with a safe explanation.
- `JV-SVC-103` can display **Waiting for administrator attention**. The nonterminal `waiting_for_auth` state keeps the same turn active: Send stays disabled, Stop remains available, and the user stays signed into JV.
- After service authentication recovers, the same remote job and Desktop turn continue without a duplicate submission. The active attention notice clears on recovery and normal completion.
- Legacy failures without support fields retain their generic behavior. Malformed or untrusted support data is rejected, arbitrary provider prose is not rendered, and stale remote codes cannot leak into later local failures.

JV CLI **0.5.2 is the recommended companion release for enhanced remote
support-code/status reporting**. Install it separately using the
[official CLI release](https://github.com/VMatee/jv-cli/releases/tag/v0.5.2).
Desktop neither bundles JV CLI nor manages its updates. The compatibility
minimum remains CLI 0.5.0 on Windows and 0.4.9 on Linux; older compatible versions
continue to work with legacy generic failure behavior.

The feature has synthetic acceptance coverage in the real native Windows Tauri
WebView, including waiting, recovery, terminal failures, malformed fields,
stale-state prevention and Stop while waiting. No production account is required
for these tests.

Stop remains local cancellation; a submitted remote job may continue and its
state may be unknown. Bridge protocol remains 1. Linux permissions are unchanged.
Windows remains explicit trusted-host execution for dedicated ordinary-user
workers: full tool filesystem access, network enabled and no approval prompts.
Keep Windows Firewall enabled. Windows installers are unsigned; verify their
bytes with the release's SHA256SUMS.
